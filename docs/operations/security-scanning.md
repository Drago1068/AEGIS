# Security Scanning

Phase 0 runs four local, tool-based scans: backend dependency vulnerabilities, frontend
dependency vulnerabilities, secret scanning, and container-image vulnerabilities. All four are
independently runnable from a local shell (no GitHub remote required) and are also wired into
the `security` job in [`.github/workflows/ci.yml`](../../.github/workflows/ci.yml); see
[ci.md](ci.md) for the local-vs-remote distinction.

## Severity threshold

**High and critical** severity findings fail the check. Low/medium findings are reported but do
not fail Phase 0's local acceptance gate. Any accepted exception (a specific CVE that cannot yet
be remediated) must be recorded below with its ID, the affected package, the reason it is
accepted, and a re-review date - never silently ignored.

**Accepted exceptions:** none at this time.

## Backend dependency scan: pip-audit

Scans the locked backend dependency set (`backend/uv.lock`) for known vulnerabilities.

```sh
cd backend
uv sync --locked --all-groups
uv export --locked --all-groups --no-emit-project --format requirements.txt -o pip-audit-requirements.txt
uv run pip-audit --strict --disable-pip -r pip-audit-requirements.txt
```

`--strict` fails the command on any finding (no accepted backend exceptions exist to
suppress). `pip-audit` cannot look up the local `aegis-backend` package itself on PyPI (it is
not published there; that is expected, not a finding), so `uv export --no-emit-project`
generates a hashed requirements file of every *real* dependency (including transitive ones)
without it, and `--disable-pip -r <file>` audits exactly that file instead of the installed
environment. `pip-audit-requirements.txt` is a disposable, gitignored artifact regenerated by
this command; it is not committed.

## Frontend dependency scan: pnpm audit

Scans the locked frontend production dependency set (`frontend/pnpm-lock.yaml`).

```sh
cd frontend
pnpm install --frozen-lockfile
pnpm audit --prod
```

`--prod` scopes the audit to production dependencies (build/test tooling vulnerabilities are
tracked but do not block Phase 0, since dev tooling never ships in the production image).

## Secret scanning: gitleaks

Scans the full git history and working tree for accidentally committed secrets, tokens, or
credentials.

```sh
# Windows (winget) / macOS (brew) / Linux: see https://github.com/gitleaks/gitleaks#installing
gitleaks detect --source . --no-git -v   # working tree only (uses .gitleaks.toml)
gitleaks detect --source . -v            # committed git history
```

`.gitleaks.toml` at the repository root allowlists vendored/build directories (`.venv`,
`node_modules`, `.next`, lockfiles, etc.) for the `--no-git` working-tree scan; they are already
excluded from version control by `.gitignore` and would otherwise produce false positives from
third-party license text and cryptography test fixtures.

No secret, token, credential, hostname, or private IP address should ever be committed; see
[configuration.md](configuration.md) for how configuration is sourced from the environment
instead.

## Container image scan: trivy

Scans the locally built backend and frontend images for OS-package and application-dependency
vulnerabilities.

```sh
docker build -f docker/backend.Dockerfile -t aegis-backend:scan ./backend
docker build -f docker/frontend.Dockerfile -t aegis-frontend:scan ./frontend

trivy image --severity HIGH,CRITICAL --ignore-unfixed --exit-code 1 aegis-backend:scan
trivy image --severity HIGH,CRITICAL --ignore-unfixed --exit-code 1 aegis-frontend:scan
```

`--ignore-unfixed` excludes vulnerabilities with no available upstream fix yet (tracked, but not
actionable today); both Dockerfiles already use pinned, minimal base images
(`python:3.12.13-slim-bookworm`, `node:24.14.0-slim`) and non-root runtime users to keep the
scannable surface small.

## What is explicitly out of scope for Phase 0

- Dynamic Application Security Testing (DAST) - there are no domain endpoints yet to test.
- Static Application Security Testing (SAST) beyond the linters/type-checkers already required
  (ruff, Pyright, ESLint, `tsc`).
- License-compliance scanning.

These may be added in a later phase via a new documented decision, per the project rule that
architecture defaults only change through a documented decision.
